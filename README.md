# Ваш агент в MAX 🚀

Подключите [Hermes Agent](https://hermes-agent.nousresearch.com/) к мессенджеру
[MAX](https://max.ru) — и общайтесь со своим ИИ-помощником прямо в чате: он слышит
голосовые, видит фото и видео, присылает карты, стикеры и файлы, умеет кнопки
подтверждения и печатает ответ ещё до того, как «додумает» его до конца.

## Что вы получаете

**Общение**
- Переписка текстом с красивым Markdown: таблицы, жирный, код — агент оформляет ответы аккуратно
- Голосовые сообщения распознаются автоматически (локальный Whisper, русский язык, бесплатно и приватно — аудио не покидает ваш сервер)
- Фото, видео, файлы и стикеры — агент видит и понимает их содержимое
- Ответы приходят «потоком»: бот показывает черновик, пока дописывает финал

**Умные кнопки**
- Опасные команды агент подтверждает кнопками «Одобрить / Отклонить» — кнопки исчезают после нажатия
- Вопросы с вариантами ответа, выбор модели и другие пикеры — всё в один тап

**Богатые ответы**
- 📍 Точки на карте — «пришли геометку Эрмитажа»
- 🧸 Стикеры — «кинь мишку с сердцем»: агент знает набор «Мишка» и подбирает стикер по описанию
- 👤 Карточки контактов, файлы, картинки, видео и аудио
- Известные стикеры не гоняются через распознавание — бот уже знает, как они выглядят, и не тратит токены

**Работа в группах**
- В групповых чатах бот отвечает на упоминания и replies; в личке — всегда
- Управление группами: закрепление сообщений, участники, админы

**Автоматизация**
- Регулярные доставки по расписанию (cron) в выбранный чат
- Память per-chat: группа и личка не смешивают контексты

## Установка за 3 шага

Нужен установленный Hermes Agent и токен бота из кабинета
[«MAX для бизнеса»](https://business.max.ru/self) (Чат-боты → ⋮ → Настройки → копировать токен).

```bash
# 1. Установите плагин (любой способ)
hermes plugins install MrYadro/hermes-max-gateway/maxbot
#   или: git clone https://github.com/MrYadro/hermes-max-gateway.git \
#        && cp -r hermes-max-gateway/maxbot ~/.hermes/plugins/

# 2. Впишите токен и разрешённых пользователей
cat >> ~/.hermes/.env <<'EOF'
MAX_ACCESS_TOKEN=ваш_токен
MAX_ALLOWED_USERS=ваш_user_id
EOF

# 3. Перезапустите гейтвей
hermes gateway restart
```

Напишите боту в MAX — он ответит. Для голосовых сообщений один раз установите
`pip install faster-whisper` в окружение hermes (модель скачается сама).

## Настройка под себя

Основное меняется в `~/.hermes/.env`:

```
MAX_ACCESS_TOKEN=...        # токен бота (обязательно)
MAX_ALLOWED_USERS=123,456   # кто может писать боту
MAX_HOME_CHANNEL=-100...    # куда приходить cron-доставке
```

Продвинутое (опционально): режим webhook вместо polling, порт и секрет вебхука,
скрытие превью ссылок — переменные `MAX_UPDATES_MODE`, `MAX_WEBHOOK_URL`,
`MAX_WEBHOOK_PORT`, `MAX_WEBHOOK_SECRET`, `MAX_DISABLE_LINK_PREVIEW`.

Приватность: память у каждого чата своя. По умолчанию агент может читать прошлые
сессии вашего профиля по просьбе из любого чата — если это не нужно, скажите
ему «не используй session_search» или ограничьте тулсет в конфиге.

### Рекомендуемый блок в `~/.hermes/config.yaml`

`platform_toolsets` раздаёт инструменты по платформам — если MAX там не
перечислен, агент останется без терминала, кода, файлов и веб-поиска (будет
говорить «нет доступа к терминалу»). Минимально достаточный набор:

```yaml
platform_toolsets:
  max:
  - hermes-max          # собственные инструменты плагина (max_pin и др.)
  - browser
  - clarify
  - code_execution
  - computer_use
  - connections
  - cronjob
  - delegation
  - file
  - image_gen
  - memory
  - session_search
  - skills
  - terminal
  - todo
  - tts
  - vision
  - web
display:
  platforms:
    max:
      cleanup_progress: true  # служебный пузырь удаляется после ответа
      tool_progress: all      # прогресс инструментов (см. «служебный пузырь» ниже)
      busy_ack_detail: false  # Working-строка без дублей — инструмент виден строкой выше
```

**Служебный пузырь.** Во время работы весь прогресс живёт в одном сообщении
прямо над полем ввода: последняя операция сверху («⚙️ browser_exec: "открываю
max.ru"»), строка «⏳ Working — N min» снизу. Пузырь правится на месте; когда
между инструментами приходит промежуточный текст — свежий пузырь
отправляется ниже, а старый удаляется, так что служебное всегда последнее.
После успешного ответа пузырь удаляется, при неудаче остаётся как breadcrumb.
Свежесть Working-строки ускоряет `HERMES_AGENT_NOTIFY_INTERVAL=60` в
`~/.hermes/.env` (дефолт 180 секунд).

`cleanup_progress` не обязателен, но приятен: статусные сообщения правятся на
месте, а после успешного ответа удаляются совсем. Неудачные прогоны оставляют
последний статус — как breadcrumbs.

## Всё на русском

Плагин уже говорит с MAX-аудиторией по-русски (подсказка платформы задаёт язык
ответов, включая описания картинок и видео). Чтобы русский был везде —
заголовки сессий, расшифровка голосовых, авто-описания входящих изображений —
добавьте в `~/.hermes/config.yaml`:

```yaml
auxiliary:
  title_generation:
    language: Russian   # названия сессий
stt:
  language: ru          # подсказка для распознавания речи
```

И одну строку в `~/.hermes/SOUL.md` (директива для агента на всех платформах):

```
Отвечай всегда по-русски — включая описания картинок и видео, заголовки сессий и короткие ответы.
```

Нюанс: промпт авто-описания входящих картинок пока захардкожен в ядре hermes
на английском (`gateway/run_inbound.py`, `analysis_prompt`). Замените его на
русский вариант вручную — учтите, что `hermes update` перезапишет файл и
правку придётся повторить.

## Частые вопросы

**Бот молчит в группе?** — Бот должен быть администратором группы: так устроен
Bot API MAX, события приходят только админам.

**Ошибки сертификатов на Linux-сервере?** — Домены MAX используют российский
корневой сертификат. Положите корни в `/usr/local/share/ca-certificates/`,
выполните `update-ca-certificates` и добавьте в `~/.hermes/.env`:
`SSL_CERT_FILE=/etc/ssl/certs/ca-certificates.crt`.

**Почему при перезапуске гейтвея нет сообщения «Gateway online»?** — Оно приходит
только после плановых перезапусков (`/restart` из чата или обновление hermes).
Обычный `systemctl restart` молчит намеренно.

**Бот может поставить реакцию на сообщение?** — Пока нет: Bot API MAX не даёт
ботам реакций. Как только откроют — добавим.

**Что бот НЕ умеет отправлять?** — Опросы (poll) и «шеринг»-карточки ссылок:
API отвечает 200, но молча выкидывает вложение; опросы тоже только из клиента.

## Профили-ассистенты: несколько «душ» у одного бота

Команда `/assistant` в любом чате (ЛС, группа, ветка комментариев канала) переключает,
какой профиль Hermes обслуживает этот чат. У каждого профиля — свой SOUL.md,
скиллы, модель и память: в одном боте живут «ассистент по работе», «домашний» и т.д.

Что нужно (один раз):

1. `gateway.multiplex_profiles: true` в config.yaml **дефолтного** профиля
2. Профили: `hermes profile create work` и т.п. — лимита на профили нет
   (лимит платформы — только на количество ботов)
3. Рестарт гейтвея

Как это работает: `/assistant` → пикер → выбор записывается в карту
`~/.hermes/maxbot-chat-memory/_chat_profiles.json` → следующие сообщения чата
получают штамп `source.profile` и уходят в сессию выбранного профиля
(официальный механизм маршрутизации ядра, тот же, что у `gateway.profile_routes`).

Нюансы:

- при переключении начинается **новая сессия** — история каждого ассистента
  сохраняется в его профиле и ждёт, когда вы вернётесь;
- **после обновления плагина** ветки комментариев переезжают на официальные
  thread-сессии: старые ветки начнутся заново (контекст прежних обсуждений
  доступен агенту через поиск по сессиям);
- ingress-доступ (allowlist) остаётся на дефолтном профиле; `/assistant`
  проходят только пользователи, разрешённые ядром;
- для веток комментариев профиль канал-wide (ключ = chat_id канала);
- в группах переключить может любой участник — переключение касается только этого чата;
- комментарии в MAX — только текст: если ассистент ветки попытается отправить
  вложение, он объяснит ограничение прямо в ветке.

## Мини-приложение Assistants

UI управления профилями чатов прямо из MAX: вкладка «Чаты» — какой профиль
обслуживает какой чат, вкладка «Профили» — карточки профилей с описаниями.
Переключение профиля — в один тап, без команд и пикеров. Это тот же механизм,
что `/assistant`, но нормальным интерфейсом на MAX UI.

**Включение.** Мини-апп живёт на webhook-порту, поэтому нужен webhook-режим:

```
MAX_UPDATES_MODE=webhook
MAX_WEBHOOK_URL=https://<домен>
MAX_ASSISTANT_ADMINS=123,456   # кому доступно управление; пусто → наследует MAX_ALLOWED_USERS
```

**Преддеплойный smoke-чек** (перед боевым включением webhook-режима):

1. Поднимите шлюз с `MAX_UPDATES_MODE=webhook` и убедитесь, что `connect()`
   прошёл без ошибок (в логе нет `config_missing`/падений старта транспорта).
2. Откройте `<MAX_WEBHOOK_URL>/max/app/` — статика мини-аппа должна отвечать.
3. Строка подписки `subscribe` в `maxbot/transports.py` не покрыта
   юнит-тестами — проверьте в логе, что подписка на обновления установлена.

Сноска: в старых ревизиях `transports.py` в вызове `subscribe(..., secret=...)`
жил плейсхолдер `self._secret` — при обновлении с них стоит сверить строку
подписки глазами.

**Активация на платформе.** В кабинете [«MAX для бизнеса»](https://business.max.ru)
мини-апп активируется нативной кнопкой в чате бота; URL мини-аппа —
`<MAX_WEBHOOK_URL>/max/app/`. Дополнительно `/assistant` после переключения
присылает кнопку «🖥 Управлять профилями» (open_app) с тем же URL.

**Локальная разработка:**

```bash
cd maxbot/webapp
npm install
npm run dev        # vite на :5173, проксирует API мини-аппа (/max/app/state, /max/app/set) на MAX_WEBHOOK_PORT
```

Бэкенд-сессию запустите с `MAX_ASSISTANT_DEV=1` и откройте в браузере
`http://localhost:5173/max/app/?dev_user_id=<id>` — dev-режим принимает
`dev_user_id` вместо initData-подписи, но отвечает только на 127.0.0.1.

**Сборка:** `npm run build` собирает `dist/`. Dist коммитится в репо —
пользователям плагин приезжает готовым; `node_modules` игнорируется.

**Безопасность:**

- API (`/max/app/state`, `/max/app/set`) доступен только админам: подпись
  initData проверяется HMAC-ом по токену бота, затем user_id сверяется с
  `MAX_ASSISTANT_ADMINS`;
- статика (`index.html`, ассеты) публична и секретов не содержит;
- dev-режим (`MAX_ASSISTANT_DEV=1`) работает только с 127.0.0.1 — не
  включайте его на публичном инстансе.

## Для инженеров

Полная карта соответствия «плагин ↔ Bot API» (все методы, вложения, обновления,
платформенные ограничения): [docs/PARITY.md](docs/PARITY.md).

Специфика MAX Bot API, проверенная живыми запросами (2026-09):

| Что | Поведение | Как обходим |
|---|---|---|
| Upload медиа | хосты требуют curl-подобный multipart (`files=`, per-part `application/octet-stream`); у video/audio токен приходит сразу в `POST /uploads` (файл отвечает `retval`), у image/file — в ответе загрузки (топ-уровень или карта `photos`) | `maxbot/uploads.py` реализует оба пути |
| Стикеры | `payload.code` = **hex(id)** из набора; десятичный id → `not.found`; с текстом не отправить | каталог «Мишка» с описаниями от vision-модели; стикеры из каталога не гоняются через vision |
| Геометка | координаты — плоские поля вложения `latitude`/`longitude` (не в `payload`) | `Attachment` несёт плоские поля |
| Fenced-код в markdown | после кириллицы до ``` парсер MAX не находит закрывающий fence и «глотает» хвост сообщения | таблицы рендерятся строками в инлайн-код (моноширинно, выравнивание живёт при переносе) |
| `message_callback` | без объекта `message` | mid клавиатуры храним в состоянии; кнопки снимаются пустым массивом вложений |
| Группы | события только админу чата | назначьте бота админом |
| Вложения в апдейте | payload пуст | догрузка `GET /messages/{mid}` |
| `types` в GET /updates | `message_callback` не в дефолте | передаём явно |
| Реакции | API не даёт ботам | — |
| Опросы / share | отправка ботам запрещена | — |

Разработка:

```bash
git clone --depth 1 https://github.com/NousResearch/hermes-agent.git ../hermes-agent
uv sync
HERMES_AGENT_SRC=../hermes-agent uv run pytest
uv run ruff check .
```
